# 동료와 다음에 할 일: 무엇을, 왜, 어디까지

이 문서가 현재 우선순위다. 이전 문서의 긴 목록을 모두 필수 추가 실험으로 해석하지 않는다.

| 구분 | 할 일 | 지금 필요한 이유 | 새 실험? |
|---|---|---|---|
| 필수 마무리 | 논문 설명과 실제 실험 설정 공동 확인 | 실제 하지 않은 주장이 없어야 함 | 아니오 |

## 1. 추가 실험을 하나 한다면: Llama 3 + CoT

**현재 비교:** Llama 2 + CoT 대 Llama 3 + SELF-DISCOVER. 모델과 방법이 동시에 달라, SELF-DISCOVER 자체가 더 좋다고 결론 낼 수 없다.

**추가할 비교:** Llama 3 + CoT 대 기존 Llama 3 + SELF-DISCOVER.

**실행 범위:** 신규 9,000건 중 이미 고정된 routed 137건만 새 CoT 구성으로 처리한다. 나머지 8,863건은 그대로 두고 전체 정확도와 교정/새 오류를 계산한다. 모델 revision, 원문 입력, Phase 1 정보 제공 조건, 양자화, 파싱과 실패 처리 등 비교 가능한 조건을 유지한다. 단계 수와 토큰 예산처럼 방법상 달라지는 조건은 미리 정해 기록한다.

**시작 전에 결정할 것:** CoT 프롬프트, decoding/토큰 예산, 주 비교와 다중검정 범위. 이미 결과를 본 뒤 계획하는 후속 분석임을 밝힌다. 137건에서 프롬프트를 반복 수정해 가장 잘 나온 것만 선택하지 않는다. 기존 SELF-DISCOVER가 예산 등에서 비교 불가능하면 조건을 맞춘 별도 실행을 계획하고 원래 결과는 보존한다.

**필수인가?** 현재처럼 'Llama 3 SELF-DISCOVER 구성에서 개선'이라고 쓰는 데 반드시 필요한 것은 아니다. 'SELF-DISCOVER가 CoT보다 낫다'를 주장하려면 직접 비교 근거가 필요하다. 연구 보강을 하나 고른다면 가장 우선 추천한다. 현재 추가 실행은 하지 않았다.

## 2. 기존 기록 확인: 우리 쪽 마무리 작업

이미 끝난 것: 9,000건 예측의 ID·정답·routing·accepted 유지 및 성능/통계 재계산.

남은 것: 두 모델 각 137건 생성 로그의 최종 답이 예측표와 맞는지, 실제 설정이 보고한 protocol과 맞는지, 입력/출력 길이 제한이 어떻게 작동했는지 확인한다. 이상이 발견되면 영향 범위를 확인하고 필요한 설명만 논문에 반영한다. 이 작업은 새 모델 학습이나 새 실험 요구가 아니다.

시간·토큰 재합산은 별도 보조 검증이다. A6b를 논문에서 뺐으므로 이 합계 검증을 논문 성능 결과의 미완료 사항으로 혼동하지 않는다. 저장소에 남긴 비용 기록을 추후 주장에 활용할 때에는 원시 호출별 합계도 대조한다.

## 3. 동료가 같이 볼 사례

Llama 3가 새로 틀리게 만든 9건은 모두 보고, 고친 36건도 가능하면 함께 검토한다. 정답 레이블과 원문이 어울리는지, 생성 이유가 실제 텍스트에 근거하는지 확인한다. 단순 공동 검토를 정식 blind 전문가 검증이나 임상 검증이라고 쓰지 않는다. 의심 사례가 있어도 원래 정답/집계를 조용히 덮어쓰지 않는다.

## 4. 제출 전 반드시 채울 부분

저자·소속·교신저자·연구비·감사문·적용되는 AI 사용 고지·약력을 확정한다. 데이터/코드 공개 가능 범위를 정하고 private 원문과 공개 aggregate를 구분한다. 최종 제출처의 형식과 수정 후 PDF를 확인한다. 저자들이 실제 설정과 논문 주장을 최종 승인한다.

## 지금 모두 추가할 필요는 없는 것

외부 corpus 평가, author-disjoint 평가, 여러 generation seed, 전체 입력 LLM 비용 baseline, 정식 전문가 annotation은 유용한 확장이지만 모두 당장 필수로 묶지 않는다. 미실시 범위를 한계로 유지한다. 심사에서 추가 요청이 나올 가능성은 있다.

## 회의에서 결정할 것 두 가지

1. Llama 3 + CoT 후속 비교를 이번 제출 전에 할 것인가? 한다면 실행 전에 조건을 확정한다.
2. 생성 로그 확인과 사례 공동 검토를 누가 맡을 것인가? 제출 정보는 각 저자가 제공한다.
