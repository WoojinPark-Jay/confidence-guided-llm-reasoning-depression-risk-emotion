# 내일 동료 검토: 남은 작업과 우선순위

## 현재 상태

기존 실험, 분류기 비교 및 A100 효율성 결과, 신규 9,000건 고정-policy 평가를 원고에 통합했다. 신규 평가는 좋은 추가 근거이나 외부 일반화나 임상적 유효성까지 완성한 것은 아니다. 아래를 모두 새 실험으로 반드시 수행해야 한다는 뜻은 아니다. 주장과 자료의 범위를 맞추는 마무리와, 선택적 연구 확장을 구분한다.

## A. 제출 준비에서 우선 처리

| 항목 | 왜 필요한가 | 완료 기준 |
|---|---|---|
| 저자/소속/교신/연구비/감사/약력 | 현재 원고에 review용 placeholder가 남아 있음 | 연구자들이 승인한 실제 정보 반영 |
| AI 사용 및 윤리/데이터 사용 설명 검토 | 실제 작성·합성 데이터 생성·연구 수행 방식과 일치해야 함 | 최종 제출처 요구와 실제 사용 범위에 맞춰 저자 승인 |
| 본문 변경 및 통계 범위 공동 승인 | 신규 holdout과 원래 결과를 혼동하지 않도록 | Table 8, Appendix F, 초록·결론 승인 |
| 결과/코드/원시 로그 보관 정리 | 내일 이후 재현과 추적이 가능해야 함 | Colab ZIP, 입력 manifest, 코드, lock, per-row 출력의 안전한 보관 및 hash 기록 |
| 최종 공개 패키지 검토 | 원문 게시물·개인정보·모델 가중치를 실수로 공개하지 않도록 | 공개 aggregate/코드와 private 원시 자료 구분 |
| 제출 직전 PDF 육안 검토 | 저자정보나 최종 문구 수정도 페이지 흐름을 바꿀 수 있음 | 최종 빌드의 표·그림·인용·페이지 검토 |

## B. 새 모델 실행 없이 가능한 보강

### 1. 생성 로그 전체와 집계 대조

현재 9,000건 예측 및 통계는 전수 검증했다. 남은 감사 범위는 Llama 2/3의 각 137개 JSON trace, Phase 1 batch 파일, 생성 config다. 이 파일들을 내려받아 ID 집합, 파싱 값, 호출 수, 토큰 및 시간 합계를 집계표와 대조하고 최대 길이 도달·입력 잘림 여부를 요약한다. 새 실험은 필요 없으며 오늘 수치를 바꾸기 위한 재실행도 아니다.

### 2. 대표 실패 및 교정 사례 공동 검토

새 Llama 3의 교정 36건/도입 9건 중 대표 사례를 보고 어떤 수정이 타당한지 확인한다. 이미 모든 결과를 봤으므로 이를 별도 blind confirmatory study로 포장하지 않는다. 필요하면 평가 지침과 검토자 수, 합의 절차를 정하고 정량 annotation agreement는 실제 수행 후에만 쓴다. 수치 계산상 정답과 원문 의미의 적절성을 구분한다.

### 3. 통계 추가는 주장에 필요할 때만

현재 'Llama 3는 Phase 1 대비 유의한 개선'이라는 주장에는 기존 비교가 충분하다. 'Llama 3가 Llama 2보다 유의하게 낫다'를 주장할 경우에만 두 구성의 직접 paired 검정과 다중비교 계획을 추가한다. 결과를 보고 유리한 검정만 선택하지 않는다. 현재 원고는 직접 우월성 주장을 하지 않아 이 추가 검정은 필수가 아니다.

## C. 연구를 강화하지만 현재 주장에 일괄 필수는 아닌 확장

| 확장 | 답할 수 있는 질문 | 현재 원고에서의 처리 |
|---|---|---|
| 복수 연구자/전문가 label 및 rationale 검토 | proxy label과 설명이 원문에 의해 지지되는가 | 아직 독립 전문가 검증으로 주장하지 않음 |
| 저자-disjoint / temporal / 외부 corpus 평가 | 다른 사용자·시기·분포에서도 유지되는가 | same-source 범위로 제한 |
| 여러 generation seed 반복 | 샘플링 변화에도 교정 이득이 안정적인가 | 현재 고정 단일 실행으로 표기 |
| 동일 모델 내 CoT/SELF-DISCOVER 교차 비교 | 개선이 모델 때문인가 prompting 때문인가 | 구성 단위 결과로 해석 |
| 동일 workload의 all-input LLM baseline | 실제 시간·에너지·비용 절감은 얼마인가 | 98.48%를 게시물 재평가 회피 비율로만 보고 |
| 시스템 전체 비용/에너지 측정 | 로딩·재시도·CPU·GPU까지 포함하면 어떠한가 | 현재 성공 호출 시간·토큰만 보고 |

이 확장은 예산과 논문의 최종 주장에 따라 결정한다. 현재 결과가 충분한지에 대한 게재 보장은 할 수 없지만, 미실시 항목을 숨기거나 측정하지 않은 효과를 주장할 필요는 없다.

## 이미 수행하여 미완료 목록에서 제외할 것

- 신규 미사용 same-source 데이터의 구성 및 frozen-pipeline 실행.
- 신규 데이터 9,000건 전체 예측 검증, 137건 라우팅 일치 확인.
- Phase 1 대비 exact McNemar, paired CI, Holm 분석.
- Phase 2 생성 시간·토큰·호출 수 기록 자체. 다만 원시 로그 재집계와 total-system cost는 별개다.
- 분류기 성능 비교와 common-A100 Phase 1 효율성 측정.

## 변경하지 말아야 할 것

새 결과를 보고 T/threshold/prompt를 다시 최적화한 뒤 같은 9,000건을 untouched 평가로 보고하지 않는다. 기존 12,000건 실험의 수치와 operational checkpoint를 새 비교 결과로 교체하지 않는다. 기존 LLM commit hash가 남아 있지 않은 것을 임의로 복원했다고 쓰지 않는다. 사례 검토에서 reference label이 의심되더라도 원래 집계를 조용히 덮어쓰지 않고 별도 adjudication 분석으로 남긴다.
