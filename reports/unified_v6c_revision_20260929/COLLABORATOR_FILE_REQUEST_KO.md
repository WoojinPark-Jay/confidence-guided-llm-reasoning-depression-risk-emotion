# 최종 SELF-DISCOVER 결과 파일 공유 요청

공동 검토용 · 2026-09-29

## 전달 요청 요약

**필수: 최종 v6c 결과 CSV 네 개. 함께 있으면: 모델별 계획 JSON 두 개와 기존 실행 설정·로그. 새 학습이나 재실행은 필요하지 않다.**

| 우선순위 | 전달할 자료 | 없을 때의 처리 |
|---|---|---|
| 먼저 전달 | Llama 2·3 × Reddit·Mixed Emotion 결과 CSV 네 개 | 현재 표는 유지하되 행별 검증·방법 간 대응 비교·최종 SD 혼동행렬은 보류 |
| 함께 전달 | 실제 재사용 계획 JSON 두 개 | 노트북에 출력된 계획으로 설명은 가능하며, 원본 파일 보관은 미완료로 남김 |
| 있으면 전달 | 전체 예측 CSV, 실행 설정 파일·로그 | 전체 예측은 재구성 가능. 설정은 실행 노트북에서 확인 가능한 범위부터 대조 |

**가장 쉬운 방법은 아래 네 결과 폴더를 구조 그대로 ZIP으로 보내는 것이다.** 파일명을 다시 짓거나 CSV를 편집할 필요는 없다.

## 요청 목적

최종 SELF-DISCOVER는 v6c로 정리했다. 전달된 실행 노트북과 요약으로 논문의 전체 성능표와 방법론은 업데이트한 상태다.

다음 단계는 **이미 저장된 게시글별 결과로 수치를 대조하고, 방법 간 비교와 오류 분석을 마무리하는 것**이다. 새로운 학습이나 추론 실행을 요청하는 것이 아니다.

## 먼저 필요한 파일: 결과 CSV 네 개

각 조건의 `sd_v6c_compact_results.csv`를 부탁한다.

| 조건 | 예상 결과 행 수 | 필요한 이유 |
|---|---:|---|
| Llama 2 · Reddit | 218 | 각 글의 SD 응답과 예측을 확인하고 기존 Direct·CoT 결과와 비교 |
| Llama 3 · Reddit | 218 | 최종 주력 모델의 수정·신규 오류 건수 확인과 방법 간 비교 |
| Llama 2 · Mixed Emotion | 86 | 스트레스 테스트의 게시글별 성능 및 오류 유형 확인 |
| Llama 3 · Mixed Emotion | 86 | 수정 28건·신규 오류 1건의 사례 확인과 최종 오류 분석 |

218건과 86건은 전체 평가셋 중 LLM으로 넘어간 글의 수다. 전체 평가셋은 각각 12,000건과 300건이다.
CSV 행 수가 위 숫자와 다르면 다시 실행하지 말고, 현재 파일과 실행 조건을 그대로 전달하면 된다.

**네 파일의 이름이 같으므로 모델·데이터별 폴더를 유지해서 보내는 것이 가장 안전하다.** CSV를 열어 정리하거나 열 이름을 바꿀 필요는 없다.

### 저장 위치 찾기

전달된 노트북의 기본 Google Drive 경로는 다음과 같다. 실행 당시 경로를 바꿨다면 실제 저장 폴더를 사용한다.

```text
내 드라이브/confidence_guided_llm_reasoning/outputs_final/unified_final/
├── phase2/
│   ├── llama2_self_discover_advanced/
│   │   └── sd_v6c_compact_results.csv
│   └── llama3_self_discover_advanced/
│       └── sd_v6c_compact_results.csv
└── mixed_emotion/phase2/
    ├── llama2_self_discover_advanced/
    │   └── sd_v6c_compact_results.csv
    └── llama3_self_discover_advanced/
        └── sd_v6c_compact_results.csv
```

## 같은 폴더에 있으면 함께 부탁하는 파일

| 파일 | 어떤 파일인가 | 활용 및 우선순위 |
|---|---|---|
| `v6c_compact_end_to_end_predictions.csv` | Phase 1 유지 사례와 SD 재평가 사례를 합친 전체 예측표 | 12,000건/300건 전체 성능을 직접 대조하기 편리하다. 없어도 기존 Phase 1 출력과 SD 결과를 합쳐 만들 수 있다. |
| `task_level_reasoning_structure_compact.json` | 실제로 생성해 재사용한 SD 풀이 계획 | 계획 본문은 노트북 출력에서 이미 확인했다. 원본 파일까지 보관해 동일 계획을 재사용할 수 있게 한다. |
| 실행 설정 파일·로그 | 모델 버전, 생성 길이, 실행 환경 등을 기록한 자료 | 논문에 적은 설정과 실제 실행 설정을 맞추는 데 사용한다. `manifest`라는 파일명이 꼭 있어야 하는 것은 아니다. 있는 자료만 전달하면 된다. |

계획 JSON은 기본적으로 `phase2/llama2_self_discover_advanced/`와 `phase2/llama3_self_discover_advanced/`에 있다.
노트북은 모델별 계획을 Reddit과 Mixed Emotion에서 공유하므로 **계획 원본은 모델별 두 개면 된다.** 데이터마다 별도로 저장해 사용했다면 해당 파일도 함께 전달한다.

설정 파일이나 로그가 없으면 이를 새로 만들기 위해 실험을 다시 실행할 필요는 없다. 전달된 실행 노트북으로 확인되는 부분과 확인되지 않는 부분을 구분해서 정리한다.

## 가장 간단한 전달 방법

**위 네 실행 폴더와 모델별 계획 JSON을 폴더 구조 그대로 ZIP으로 묶어 전달하면 된다.** 폴더가 너무 크면 우선 결과 CSV 네 개만 보내도 검증을 시작할 수 있다.

모델 가중치 전체, Hugging Face 토큰, 계정 정보, Google Drive 전체는 필요하지 않다. 토큰이나 비밀번호가 들어 있는 설정 파일은 비밀값을 제거한 사본으로 전달한다.

## 파일을 받으면 진행할 작업

1. 게시글 ID로 기존 Phase 1·Direct·CoT·최종 SD 예측을 맞춘다.
2. 누락·중복을 확인하고 정확도, Macro F1, 수정·신규 오류를 다시 집계한다.
3. SD와 CoT, SD와 Direct가 같은 글에서 어떻게 달랐는지 통계적으로 비교한다.
4. 최종 혼동행렬과 클래스별 성능을 만들고 논문 표·그림을 확정한다.

현재 남은 파싱 실패는 실패로 유지한다. 최종 라벨이 추출되지 않은 경우 기존 Phase 1 예측을 유지하는 현재 규칙을 사용하며, 정답에 맞춰 라벨을 넣거나 해당 사례만 재생성하지 않는다.

## 현재 자료와 추가 자료의 차이

| 현재 자료로 가능한 일 | 추가 CSV가 있어야 정확히 마무리할 일 |
|---|---|
| 전체 성능표와 본문 작성 | 게시글별 결과 대조 및 누락·중복 확인 |
| 실제 코드의 프롬프트와 계획 설명 | 클래스별 F1와 최종 Phase 2 혼동행렬 |
| 수정·신규 오류 합계로 Phase 1 대비 정확도 검정 | SD와 CoT·Direct 사이의 같은 사례 대응 검정 |

노트북과 요약 자료를 다시 작성할 필요는 없다. **현재 가장 필요한 추가 전달물은 v6c 결과 CSV 네 개**다.
